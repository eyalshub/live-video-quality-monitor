# API contract

Source of truth at runtime: FastAPI's OpenAPI schema (`/openapi.json`). Frontend types are generated
from it (`npm run gen:api`, ADR-008). This document explains behavior the schema cannot express.

Status: all endpoints below are implemented (P1). Routes with a session id declare `ErrorResponse`
for 404 and 422 in OpenAPI.

## Conventions
- JSON only. Timestamps are ISO-8601 UTC. IDs are UUIDs generated by the server.
- Every response carries `X-Request-ID` (echoed from the request, or generated).
- CORS: only origins listed in `CORS_ORIGINS` are allowed.

### Error body (every error, including validation errors)
```json
{ "error": { "code": "validation_error", "message": "Request validation failed", "details": [ ... ] } }
```
| Status | `code` | When |
|---|---|---|
| 404 | `not_found` | Unknown route or unknown session |
| 405 | `method_not_allowed` | Wrong method |
| 422 | `batch_too_large` | More than `MAX_SAMPLES_PER_BATCH` samples; `details` = `{max, received}` |
| 422 | `validation_error` | Missing fields, wrong types, out-of-range values; `details` = list of `{loc, msg, type}` |
| 422 | `inconsistent_verdict` | verdict/reason do not match the values + the session's thresholds (ADR-002); `details` = list of `{t, expected, received}` |
| 500 | `internal_error` | Unexpected; no stack trace in the body |

## Endpoints

Requests are all-or-nothing: if any sample is invalid, nothing from that request is written.

### `GET /health`
- 200 `{"status": "ok", "db": "ok"}`
- 503 `{"status": "degraded", "db": "error"}` — a status report, intentionally **not** the error body,
  so monitors and the frontend can read the same shape in both cases.

### `POST /sessions`
Request: no body (a body is ignored; clients cannot choose thresholds). Response 201:
```json
{ "id": "uuid", "started_at": "2026-11-08T12:00:00Z",
  "thresholds": { "fps_min": 15, "brightness_min": 60, "brightness_max": 200, "motion_max": 20 },
  "max_samples_per_batch": 120 }
```
`max_samples_per_batch` lets the client split a large outbox (after a long network drop) into
requests the server accepts, without a second copy of the setting in frontend config.

### `POST /sessions/{id}/samples`
Request: `{ "samples": [Sample, ...] }` (1..`MAX_SAMPLES_PER_BATCH`).
```json
{ "t": 12, "fps": 29.6, "brightness": 132.4, "motion": 3.1, "face": true, "verdict": "good", "reason": null }
```
- `t` int ≥ 0; `fps` 0–120; `brightness` 0–255; `motion` 0–255 or `null` (ADR-009); `face` bool;
  `verdict` `good|poor`; `reason` one of `no_face|too_dark|too_bright|hold_still|low_fps` or `null`.
- Every key is required (`motion` and `reason` may be `null`); unknown keys are rejected; types are
  strict (`"30"` is not a number, `1` is not a boolean); NaN/Infinity are rejected.
- Values must already be rounded to 1 decimal (ADR-003).
- Same `t` twice in one batch → the first one wins (the repeat counts as a duplicate).
- A resent `t` is never overwritten: first write wins.
- Response 200: `{ "inserted": n, "duplicates": m, "ignored_after_stop": k }`.
- Session ended (ADR-010): always 200, nothing is written. Existing `t` → `duplicates`;
  new `t` → `ignored_after_stop`. Validation (422) still applies first.

### `POST /sessions/{id}/stop`
Request: optional `{ "samples": [Sample, ...] }`; no body or `{}` is fine.
Saves the samples and sets `ended_at` in one transaction (ADR-004). If a final sample is invalid →
422 and the session stays open. Calling again → 200 with the same `ended_at`; its samples follow
ADR-010. Response 200:
```json
{ "session": { "id": "...", "started_at": "...", "ended_at": "...", "thresholds": { }, "summary": { } },
  "ingest": { "inserted": 2, "duplicates": 0, "ignored_after_stop": 0 } }
```

### `GET /sessions`
Newest first (`started_at DESC`). Each item: `id, started_at, ended_at, thresholds, summary`.

### `GET /sessions/{id}`
Session + `samples` ordered by `t` + `summary`.

### Summary object
```json
{ "duration_s": 42, "avg_fps": 28.7, "face_pct": 93.0, "good_pct": 81.0, "sample_count": 40 }
```
Computed with SQL aggregates at read time: `duration_s = max(t)`, averages and percentages rounded to
1 decimal. All fields except `sample_count` are `null` for a session with no samples. A session closed
without Stop has `ended_at = null` and its duration is still the last `t`.
