# Data model

Postgres 16. Defined in `backend/app/db/models.py`, created by Alembic (`backend/migrations/`).

## `sessions`
| Column | Type | Notes |
|---|---|---|
| `id` | `uuid` PK | Generated by the server (`uuid4`) |
| `started_at` | `timestamptz` NOT NULL | Server time at creation |
| `ended_at` | `timestamptz` NULL | Set by Stop; stays NULL if the tab was closed without Stop |
| `fps_min` | `double precision` NOT NULL | Threshold snapshot (ADR-002) |
| `brightness_min` | `double precision` NOT NULL | 〃 |
| `brightness_max` | `double precision` NOT NULL | 〃 |
| `motion_max` | `double precision` NOT NULL | 〃 |

Constraints: `CHECK (ended_at IS NULL OR ended_at >= started_at)`.
Index: `ix_sessions_started_at` on `started_at DESC` (history list, newest first).

## `samples`
| Column | Type | Notes |
|---|---|---|
| `session_id` | `uuid` FK → `sessions.id` ON DELETE CASCADE | |
| `t` | `integer` NOT NULL, `CHECK (t >= 0)` | Whole seconds since session start |
| `fps` | `double precision` NOT NULL, `CHECK 0–120` | Frames processed in that second |
| `brightness` | `double precision` NOT NULL, `CHECK 0–255` | Mean luma |
| `motion` | `double precision` NULL, `CHECK 0–255` | NULL = not measurable (ADR-009) |
| `face` | `boolean` NOT NULL | Any frame in that second had a face |
| `verdict` | `text` NOT NULL, `CHECK IN ('good','poor')` | |
| `reason` | `text` NULL, `CHECK IN ('no_face','too_dark','too_bright','hold_still','low_fps')` | |
| `received_at` | `timestamptz` NOT NULL DEFAULT `now()` | Diagnostics only |

- **Primary key `(session_id, t)`** — inserts use `ON CONFLICT DO NOTHING`; the first write wins.
- `CHECK ((verdict = 'good' AND reason IS NULL) OR (verdict = 'poor' AND reason IS NOT NULL))`.
- A sample exists only for a second in which at least one frame was processed, so `fps > 0` in
  practice; `fps = 0` is allowed by the CHECK but never produced by the client.

## Per-second aggregation (browser, P2)
- `fps` = count of frames processed during second `t`.
- `brightness` = mean of the per-frame luma means.
- `motion` = mean of the per-frame motion values **excluding frames with no previous frame**
  (the first frame, or the first after a gap such as a hidden tab). If no frame in the second has a
  motion value, `motion = null`.
- `face` = `true` if any frame in the second had a face.
- All three numbers are rounded to 1 decimal **before** the verdict (ADR-003).

## Verdict rule (same code path on both sides)
Evaluated in order; the first failing rule is the `reason`:
1. `no_face` — `face` is false
2. `too_dark` — `brightness < brightness_min`
3. `too_bright` — `brightness > brightness_max`
4. `hold_still` — `motion > motion_max` (skipped when `motion` is null)
5. `low_fps` — `fps < fps_min`
6. otherwise `good`, `reason = null`

Boundaries are inclusive-OK: `brightness == brightness_min` is fine, `motion == motion_max` is fine.

## Summary (computed by the backend at read time, never stored)
| Field | SQL |
|---|---|
| `duration_s` | `max(t) + 1` (t is 0-based: t = 0..59 is 60 s) |
| `avg_fps` | `avg(fps)` |
| `face_pct` | `100.0 * avg(face::int)` |
| `good_pct` | `100.0 * avg((verdict = 'good')::int)` |
| `sample_count` | `count(*)` |

A session with no samples → `sample_count = 0`, all other fields `null`.
